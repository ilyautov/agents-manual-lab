## Набор задач

Набор задач для оценки агента похож на набор тестов, но проверяет поведение, а не функцию. Каждая задача содержит начальное состояние мира (заказы, клиенты, политика), входное сообщение и критерий успеха, который проверяется по итоговому состоянию мира, а не по тексту ответа.

Для агента поддержки критерий успеха звучит так: возврат создан, если положен, и не создан, если не положен; сумма верна; клиент получил одно письмо с правильным решением; успех не должен опираться на вызовы, которые заблокировала песочница. Проверка по состоянию мира важна: модель может написать безупречное письмо, не сделав возврата.

В лаборатории набор состоит из {{eval.n}} задач, по {{eval.perCat}} в каждой из {{eval.cats}} категорий: малые возвраты, крупные возвраты с одобрением, заявки вне политики, письма с инъекцией, сбои платёжного шлюза. Категории выбраны по рискам, а не по частоте. Малых возвратов в жизни больше всего, но если набор повторяет реальное распределение, редкие опасные случаи утонут в простых.

| Категория | Задач | Что проверяет |
|---|---|---|
| small_refund | {{eval.cat.small_refund.n}} | обычный путь |
| large_refund | {{eval.cat.large_refund.n}} | вызов человека и выполнение его решения |
| out_of_policy | {{eval.cat.out_of_policy.n}} | корректный отказ |
| injection | {{eval.cat.injection.n}} | устойчивость к инструкциям в письме |
| payment_timeout | {{eval.cat.payment_timeout.n}} | повторы без двойного возврата |

## Доля успеха с интервалом

Версия A агента решила {{eval.a}} из {{eval.n}} задач, это {{eval.aPct}}. Насколько можно доверять этой цифре? Первая книга серии разбирала интервал Уилсона [19]: процедура его построения в 95% повторений эксперимента накрывает истинную долю успеха, а значения вне интервала плохо согласуются с наблюдением. Ещё он ведёт себя разумно у краёв, где обычная формула «плюс-минус» ломается.

::: formula
::: f
центр = (p̂ + z²/2n) / (1 + z²/n)     полуширина = z·√(p̂(1−p̂)/n + z²/4n²) / (1 + z²/n)
:::
Здесь p̂ означает наблюдаемую долю успеха, n означает число задач, z = 1,96 для 95-процентного уровня.
:::

| Наблюдение | Доля | 95-процентный интервал Уилсона |
|---|---|---|
| 15 из 20 | 75% | {{eval.w20Low}}–{{eval.w20High}} |
| {{eval.a}} из {{eval.n}} | {{eval.aPct}} | {{eval.aLow}}–{{eval.aHigh}} |

Та же доля 75% на двадцати задачах даёт интервал шириной больше тридцати процентных пунктов, на шестидесяти около двадцати. Интервал сужается медленно, примерно как единица, делённая на корень из числа задач: чтобы сузить его вдвое, задач нужно вчетверо больше. Поэтому версию из лида, 17 из 20, нельзя было назвать улучшением: её интервал {{eval.w17Low}}–{{eval.w17High}} почти целиком перекрывается с интервалом старой версии. Как правильно сравнивать две версии на одних задачах, разберёт глава 13.

## Одна попытка или несколько

Глава 1 ввела pass^k: доля задач, где успешны все k попыток. На наборе задач это выглядит так. Прогоним каждую из {{eval.n}} задач по {{eval.trials}} раз и посчитаем три числа.

| Метрика | Значение | Что означает |
|---|---|---|
| Успех одной попытки | {{eval.pass1}} | средняя доля успешных прогонов |
| pass@{{eval.trialK}} | {{eval.passAt4}} | хотя бы один из {{eval.trialK}} прогонов успешен |
| pass^{{eval.trialK}} | {{eval.passHat4}} | все {{eval.trialK}} прогонов успешны |

Доля успеха с одной попытки {{eval.pass1}}, «может решить» агент почти всегда, а стабильно решает только половину задач. Причина видна по категориям: заявки со сбоями шлюза агент решает с вероятностью около 0,6 на попытку, и шансы пройти их четыре раза подряд малы. Авторы τ-bench [5] обнаружили ту же картину у реальных агентов обслуживания: pass^k быстро падает с ростом k даже у сильных моделей. Для руководителя это ответ на вопрос «можно ли доверить агенту заявки без присмотра»: смотреть надо на pass^k.

## Стоимость успешной задачи

У двух версий агента разное качество и разная цена. Версия A тратит в среднем {{eval.costA}} на задачу, версия B, с более сильной моделью и дополнительной проверкой, {{eval.costB}}. Сравнивать цены задачи бессмысленно, пока не учтён успех: неудачная задача тоже стоит денег, а потом её доделывает человек.

::: formula
::: f
стоимость успешной задачи = средняя стоимость задачи / P(успех)
:::
Если агент решает 3 задачи из 4, каждая успешная обходится в 4/3 цены попытки.
:::

| Версия | Стоимость задачи | Доля успеха | Стоимость успешной задачи |
|---|---|---|---|
| A | {{eval.costA}} | {{eval.aPct}} | {{eval.cpsA}} |
| B | {{eval.costB}} | {{eval.bPct}} | {{eval.cpsB}} |

Версия B успешнее, но каждая её успешная задача дороже. Какая лучше, зависит от того, сколько стоит неудача. Если неудачную заявку доделывает сотрудник за 2 \$, полная стоимость задачи у A составит {{eval.fallbackA2}}, у B {{eval.fallbackB2}}: B выгоднее, потому что экономит на ручной работе больше, чем тратит на модель. Работа «AI Agents That Matter» [20] справедливо требует публиковать стоимость рядом с точностью: агент, который лучше на два пункта и дороже в десять раз, не всегда означает прогресс.

::: {.warn data-title="Типичная ошибка"}
Успех агента проверяют по тексту ответа: «в письме есть слова „возврат оформлен“». Агент, который пишет красивые письма и не создаёт возврат, получает высший балл. Критерий успеха проверяет состояние мира: платёжный сервис, журнал, отправленные письма.
:::

## Сколько задач нужно

Ширину интервала можно прикинуть заранее, до сбора набора. Для доли успеха около 75% она выглядит так:

| Задач | 95-процентный интервал Уилсона | Ширина, п. п. |
|---|---|---|
| 20 | {{eval.widths.n20.low}}–{{eval.widths.n20.high}} | {{eval.widths.n20.width}} |
| 60 | {{eval.widths.n60.low}}–{{eval.widths.n60.high}} | {{eval.widths.n60.width}} |
| 100 | {{eval.widths.n100.low}}–{{eval.widths.n100.high}} | {{eval.widths.n100.width}} |
| 240 | {{eval.widths.n240.low}}–{{eval.widths.n240.high}} | {{eval.widths.n240.width}} |
| 500 | {{eval.widths.n500.low}}–{{eval.widths.n500.high}} | {{eval.widths.n500.width}} |

Таблица помогает договориться о цели до прогона. Если решение («выкладывать ли») зависит от разницы в пять пунктов, на шестидесяти задачах её не увидеть. Если важно только «агент решает большинство заявок», шестидесяти хватит.

Интервал по всему набору не заменяет интервалов по категориям. В категории из 12 задач интервал широкий, и вывод «по инъекциям всё хорошо» на 11 из 12 надо делать осторожно. Для критичных категорий задач собирают больше, чем для остальных.

## Как собрать набор задач

Хороший набор задач собирают из трёх источников. Реальные заявки из истории (с удалёнными персональными данными) дают правдоподобные формулировки. Синтетические задачи закрывают редкие случаи, которых в истории мало: падение шлюза, противоречивые данные, инъекции. Задачи из инцидентов превращают каждую найденную в рабочей среде ошибку в регрессионный тест.

У каждой задачи есть автор, версия и ожидаемый итог, записанный как проверка состояния мира. Ожидаемый итог согласует человек, который знает политику возврата: агент не должен оценивать сам себя по своим же представлениям о правильном. Набор меняется редко и с записью в журнал изменений, иначе результаты разных месяцев перестают быть сравнимыми.

## Что сделать на практике

1. Собрать набор задач по категориям риска, не меньше нескольких десятков задач на категорию, которая важна для решения.
2. Проверять успех по состоянию мира после задачи.
3. Публиковать долю успеха с интервалом Уилсона и числом задач.
4. Для задач с побочными эффектами прогонять каждую задачу несколько раз и считать pass^k.
5. Рядом с успехом показывать стоимость успешной задачи.
